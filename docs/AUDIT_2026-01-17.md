# System Audit – January 17, 2026

## Summary

Audit was requested after reports of the system crashing. Root cause and mitigations are below.

---

## 1. Root cause: crash on import

**Symptom:** Process exits during startup, often before any log output.

**Cause:** In `scanners/technical_scanner.py`, type hints reference `pd.DataFrame` (e.g. `-> Optional[pd.DataFrame]`). When `pandas` is not installed or fails to import, `pd` is never defined. At class definition time Python evaluates these type hints and raises:

```text
NameError: name 'pd' is not defined
```

**Fix applied:** Added `from __future__ import annotations` at the top of `scanners/technical_scanner.py`. Annotations are then treated as strings and not evaluated at import time, so `pd` is not required for loading the module.

**Files changed:** `scanners/technical_scanner.py`

---

## 2. Logging robustness

**Risk:** If the log directory is missing or not writable (e.g. read-only filesystem, permission issues), `logging.FileHandler(Config.LOG_PATH / "agent.log")` can raise and prevent the agent from starting.

**Fix applied:** In `agent.py`, log setup now:
- Builds the list of handlers (always includes stdout).
- Tries to create `Config.LOG_PATH` and add a file handler; on failure, logs a warning and continues with stdout only.

**Files changed:** `agent.py`

---

## 3. API and dependency check

- **Logs API** (`api/logs_api.py`): Uses FastAPI and `get_db()`; no import-time dependency on scanners. Safe as long as `storage.database` is importable.
- **Config:** `Config.LOG_PATH.mkdir()` is still called at the end of `config.py`; `agent.py` also calls `mkdir` before adding the file handler, so startup is resilient if config runs first.
- **Requirements:** `requirements.txt` includes `pandas>=2.0.0` and `alpaca-py>=0.13.0`. In a full install, `pd` and Alpaca are available; the `from __future__ import annotations` fix ensures that optional or failed imports do not crash the process.

---

## 4. Recommendations

1. **Deployment:** Ensure `pip install -r requirements.txt` runs in the deployment environment so `pandas` and `alpaca-py` are present. The annotation fix prevents crashes if they are missing or fail to load.
2. **Logs:** If the app still crashes on Railway, check:
   - Build logs: confirm all dependencies install (e.g. no `pip` or platform errors).
   - Runtime logs: look for the first exception or traceback after “Starting Gann Sentinel Agent…” or “INITIALIZING”.
3. **APIs:** To confirm external APIs from the running app:
   - **Health:** `GET /health` (no auth).
   - **Logs (protected):** `GET /api/logs?token=LOGS_API_TOKEN&limit=10`.
   - **Status (protected):** `GET /api/status?token=LOGS_API_TOKEN`.
4. **Portfolio sync:** `_sync_portfolio_to_db()` is already wrapped in try/except; Alpaca errors there are logged and do not stop startup.
